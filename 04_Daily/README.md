# Daily

## Module Responsibility

- Manage current daily focus.
- Support short-term execution.
- Clarify daily prioritization.
- Define daily briefing rules.
- Define daily review rules.
- Provide lightweight review of what needs attention now.

## Operating Rules

- Daily planning must serve real life, not create administrative overhead.
- Yu-AI-OS maintenance must not displace important learning or daily responsibilities.
- Health and sleep have priority when they materially affect performance.
- Hard deadlines and school obligations must be surfaced clearly.
- Keep the daily system lightweight.
- Do not turn this module into a large task-management application.
- Daily briefing and daily review are separate documents with different responsibilities.

## Daily Operating Cycle

- `00:00` Asia/Tokyo: the user finishes work and the system initiates confirmation of the day's actual plan completion.
- `00:30` Asia/Tokyo: an external ChatGPT scheduled workflow produces a mobile-friendly Chinese daily review when confirmed data exists.
- Do not infer completion, postponement, unexpected additions, health status, or score inputs.
- This repository documents the workflow; it does not automatically schedule ChatGPT notifications or send reviews.

## Boundaries

- Long-term career direction belongs in `01_Career`.
- Learning state belongs in `02_Learning`.
- Software project execution belongs in `03_Project`.
- Stable references belong in `05_Reference`.
- External developments belong in `04_Daily/Briefing.md`.
- The user's actual day belongs in `04_Daily/Review.md`.
